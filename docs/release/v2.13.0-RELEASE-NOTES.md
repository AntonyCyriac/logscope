# v2.13.0 — Quality & Integrity (Hardening Wave 1)

**Type:** Minor (trust / correctness — storage + plugin integrity)  
**Baseline:** `v2.12.1`  
**ADR:** [ADR-005-M11.1 Index Integrity Hardening](../architecture/decisions/ADR-005-M11.1-Index-Integrity-Hardening.md)

## Summary

`v2.13.0` makes index reuse and plugin-backed persistence **fail closed** when integrity cannot be proven. Correctness failures surface as explicit errors — never silent stale search results or exit code 0 after a plugin write failure.

**Integrity Gate (Wave 1):**

```text
#188: same-size rewrite → rebuild (content hash mismatch)
#189: mid-file edit + growth → rebuild (prefix hash mismatch)
#195: unsupported future schema → Error (no silent DB overwrite)
#203: plugin append_line/finalize failure → analyze Error
```

## Fixed

### Storage index integrity ([#188](https://github.com/AntonyCyriac/logscope/issues/188), [#189](https://github.com/AntonyCyriac/logscope/issues/189))

- Persist `source_content_sha256` and prefix hash in index metadata at `finalize()`
- Equal-size in-place rewrites no longer reuse a stale index
- Mid-file edits before append growth trigger rebuild instead of retaining a stale prefix
- mtime-only changes with identical content still allow reuse

### Schema compatibility ([#195](https://github.com/AntonyCyriac/logscope/issues/195))

- Indexes with `schema_version` above the supported maximum return an explicit error
- Unsupported-schema DBs are not silently deleted or overwritten

### Plugin storage errors ([#203](https://github.com/AntonyCyriac/logscope/issues/203))

- Non-zero plugin `append_line` / `finalize` status propagates through `AnalysisEngine`
- CLI analyze/investigate exits non-zero; web analyze returns an error response

## Changed

- `--reuse-index` may rebuild or fail more often when source content or schema integrity cannot be verified — **intentional** correct behavior
- Partial in-memory index truncation still emits the existing WARNING (not a hard abort)

## Upgrade notes

- Rebuild CLI/web/desktop from tag `v2.13.0`
- No new CLI flags required for correct behavior
- No REST/CLI JSON shape changes; no investigation-domain or desktop/web UX changes
- If analyze fails with unsupported schema, upgrade the tool or remove the incompatible index file manually — the DB is preserved
