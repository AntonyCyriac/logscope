# v2.10.1 — Storage hotfix (#163, #164)

**Type:** Patch (post–`v2.10.0` storage regressions)  
**Baseline:** `v2.10.0`  
**ADR:** None (storage-layer fix; no manifest/API change)

## Summary

Fixes two storage backlog issues: **concurrent index creation** failing with misleading `disk I/O error` ([#163](https://github.com/AntonyCyriac/logscope/issues/163)), and **`compress_content` wasting CPU** when compression never shrinks rows ([#164](https://github.com/AntonyCyriac/logscope/issues/164)).

## Fixed

### [#163](https://github.com/AntonyCyriac/logscope/issues/163) — concurrent index create

- Exclusive **`*.build.lock`** during index build (wait up to 30s)
- Build into **`*.building`**; atomic promote to final path on **`finalize()`**
- No destructive `remove()` of the target DB before open (root cause of concurrent `SQLITE_IOERR`)
- Reopen final DB after promote so post-`finalize()` reads still work

### [#164](https://github.com/AntonyCyriac/logscope/issues/164) — compression wasted work

- **Adaptive short-circuit:** after 32 attempts with 0 wins, skip `compressZlib` for remainder of run
- Meta on finalize: `content_compression_attempts`, `content_compression_wins`, `content_compression_adaptive_disabled`
