# v2.6.1 — Pstack fault-thread hotfix (v2.6.0 follow-up)

**Type:** Patch  
**Baseline:** `v2.6.0`  
**Regression:** [#129](https://github.com/AntonyCyriac/logscope/issues/129)  
**Fix PR:** [#130](https://github.com/AntonyCyriac/logscope/pull/130)

## Summary

Fixes a **v2.6.0 regression** where `PstackCrashAnalyzer` picked the **first thread in the dump** as the fault thread when no GDB `Program received signal` or `[Switching to thread N]` marker was present. Plain `pstack` output often lists idle workers first, producing misleading observations such as "Fault in epoll_wait".

## Fixed

- **`crash_analyzer.cpp`** — score threads by signal/abort-chain frames; de-prioritize idle-top threads (`epoll_wait`, `pthread_cond_wait`, `grpc_*`, etc.); report the top **application** frame in observations and summary

## Added (tests)

- `SelectsAbortThreadWhenNotListedFirstWithoutSignalLine` — issue #129 reproduction
- `FallsBackToFirstThreadWhenAllIdle` — fallback when every thread is parked

## Upgrade notes

No manifest, API, or config changes. Rebuild and redeploy `logscope`, `logscope-web`, and `logscope-desktop` from tag `v2.6.1`.
