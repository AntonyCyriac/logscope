# v2.12.1 — Desktop Timeline refresh fix

**Type:** Patch (desktop bugfix — Bugbot PR #184 finding #2)  
**Baseline:** `v2.12.0`  
**ADR:** (none — behavior fix only; see [ADR-008-M14.2](../architecture/decisions/ADR-008-M14.2-Desktop-Evidence-Suggestions.md))

## Summary

Fixes a desktop Timeline bug where **adding an artifact after Load more** could show a **stale timeline** because `refresh()` did not reset pagination offset. Also fixes **Load more** incorrectly calling `refresh()` (which would reset the table after this fix).

## Fixed

- **`TimelinePanel::refresh()`** — always `clearTable()` and reload from offset 0 (artifact add, investigation reload)
- **In-flight refresh** — queued refresh discards stale worker result and starts a full reload
- **Load more** — calls `startAsyncLoad()` to append pages without resetting

- Web and CLI unchanged
