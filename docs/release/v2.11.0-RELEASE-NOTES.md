# v2.11.0 — Desktop Timeline + Crash parity (P2)

**Type:** Minor (P2 — desktop investigation parity)  
**Baseline:** `v2.10.1`  
**ADR:** [ADR-008-M14.1 Desktop Investigation Parity](../architecture/decisions/ADR-008-M14.1-Desktop-Investigation-Parity.md)

## Summary

Desktop (`logscope-desktop`) gains the **Investigation** workflow surfaces that shipped on web through Stories 1–6 + P1: **Timeline** and **Crash** bottom-dock tabs, backed by the same `workspace::Investigation` contracts as CLI and REST — not a second domain model.

**Story Gate path:**

```text
Create investigation → add log + pstack → Timeline → crash.summary → Crash → fault thread → pstack highlight
```

## Added

### Investigation mode (desktop)

- **Investigation** menu — New / Open / Close / Add Artifact
- **Artifact sidebar** when an investigation is active
- **`InvestigationController`** (`apps/common/`) — thin façade over `workspace::Investigation`

### Timeline + Crash tabs

- Bottom dock order: **Timeline · Crash · Results · AI · Analytics**
- **Timeline** — `projectTimeline()` including `crash.summary` (P1)
- **Crash** — `analyzeCrash()` with signal, threads, embedded pstack viewer
- **`ViewerNavigation`** — cross-tab jumps (timeline log line → Results; `crash.summary` → Crash; fault thread → highlight)

### Tests

- `logscope_desktop_parity_test` — Story Gate headless scenarios (tab gating, open round-trip, full crash path)
- `InvestigationControllerTest` — unit coverage for controller delegation

## Known limitation (v2.11.0)

> **Synchronous Timeline/Crash refresh** on the UI thread when a tab is activated. This is a deliberate v2.11.0 trade-off for the parity slice — **not an architectural defect**. Background loading is a performance follow-up; domain contracts are unchanged.

See [V211-DESKTOP-PARITY-SCENARIOS.md](../planning/V211-DESKTOP-PARITY-SCENARIOS.md) § Known limitation.
