# v2.9.0 — Crash Timeline (P1)

**Type:** Minor (P1 — Crash Timeline)  
**Baseline:** `v2.8.0`  
**ADR:** [ADR-009-M15.9 Crash Timeline](../architecture/decisions/ADR-009-M15.9-Crash-Timeline.md)

## Summary

Investigations now surface **`crash.summary`** on the **Timeline** — crash evidence from existing Story 4 `CrashReport` analysis appears in chronological context with log events. Engineers select a crash row and jump to Crash tab evidence without leaving the incident narrative.

> P1 makes existing crash analysis visible in the investigation timeline; it does not make crash analysis smarter.

## Story Gate demo

```text
Create investigation → Add app.log → Add pstack
  → Open Timeline → crash.summary (SIGSEGV) among log events
  → Select row → Crash tab / pstack evidence
```

Works via **web** (Playwright Crash Timeline E2E), **REST/CLI** (`GET …/timeline`, `investigation timeline`).

## Added

### Domain (`scope_workspace`)

- `crash.summary` `TimelineEvent` from `CrashReport` via timeline projection enricher
- One summary per pstack/core artifact; replaces `artifact.attached` for those types only
- Degraded rows for `unavailable` / `failed` analysis status
- Stable `TimelineEvent.id` via `makeTimelineEventId`; timestamp from `artifact.importedAt` (v2.9.0)

### Web (`logscope-web`)

- Timeline **Crash** row styling; click navigates to Crash tab for artifact
- Playwright Crash Timeline E2E in CI Web Build Smoke

## Upgrade notes

- No manifest schema change — crash reports remain ephemeral projections
- pstack/core artifacts no longer emit `artifact.attached` on timeline; they emit `crash.summary` instead
- Rebuild and redeploy `logscope`, `logscope-web`, and `logscope-desktop` from tag `v2.9.0`
