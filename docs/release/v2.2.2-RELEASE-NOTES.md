# v2.2.2 — API key hashing (security patch)

**Type:** Patch (no milestone ceremony)  
**Baseline:** `v2.2.1`

## Summary

`logscope-web` no longer requires storing API keys in plain text in properties files. Operators can store a salted SHA-256 hash via `web.api_key_hash`. Legacy `web.api_key` and `LOGSCOPE_WEB_API_KEY` remain supported.

## Added

- `web.api_key_hash` — `sha256:<salt_hex>:<digest_hex>` at rest
- `LOGSCOPE_WEB_API_KEY_HASH` environment override
- `logscope-web --hash-api-key <secret>` — prints a hash for config files
- Startup warning when plaintext `web.api_key` is loaded from config

## Migration

1. Generate hash: `logscope-web --hash-api-key 'your-secret'`
2. Set `web.api_key_hash=<output>` in properties
3. Remove `web.api_key` from committed config (keep secret in env/secret manager if preferred)

**Containers:** continue using `LOGSCOPE_WEB_API_KEY` (plain) — not written to disk.

## Test baseline

Web unit + integration tests cover plaintext and hashed credentials. Run `ctest -L scope_web_tests` and `ctest -L logscope_web_integration_tests`.
