# v2.4.1 — Artifact metadata hotfix (v2.4.0 follow-up)

**Type:** Patch  
**Baseline:** `v2.4.0`  
**Regression:** [#119](https://github.com/AntonyCyriac/logscope/issues/119)  
**Fix PR:** [#120](https://github.com/AntonyCyriac/logscope/pull/120)

## Summary

Fixes a **v2.4.0 regression** where `artifacts[].metadata` (e.g. `role`, `sizeBytes`) was not persisted in `manifest.json`. Web GET investigation and CLI `show` could display empty metadata after reload even though ingest had set values.

## Fixed

- **`investigation_manifest_io.cpp`** — serialize and parse `artifacts[].metadata` on save/load

## Added (tests)

- Workspace metadata round-trip unit test
- CLI investigation command + legacy parser tests (`create`, `add-note`, `list`, `show`)
- Web integration: `POST .../open` with pstack → **409** `ARTIFACT_NOT_OPENABLE` (MS.6)
- Web integration: `GET .../investigations/{id}` asserts `isEntry` and `metadata.role`
- Web request parser and REST JSON unit tests for Story 2 fields

## Upgrade notes

- **Recommended** for anyone using Story 2 multi-artifact investigations with `role` or `sizeBytes` metadata on `v2.4.0`.
- No API or CLI flag changes; existing investigations re-saved after upgrade will persist metadata correctly.
