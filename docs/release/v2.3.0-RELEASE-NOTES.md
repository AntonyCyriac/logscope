# v2.3.0 — Create an Investigation (Story 1)

**Type:** Minor (Phase A — Story 1)  
**Baseline:** `v2.2.2`  
**ADR:** [ADR-009-M15.5 Investigation Container](../architecture/decisions/ADR-009-M15.5-Investigation-Container.md)

## Summary

LogScope introduces the **Investigation** as the product noun: a portable incident container with multiple **artifacts** (log + note), save/reopen, and entry-artifact open into analyze/investigate. Builds on M15.3 shared workspaces with manifest v1 persistence; `/api/v1/workspaces` remains an alias.

## Story Gate demo

```text
Create Investigation → Add log → Add note → Save → Reopen
```

Works via **web** (Investigations panel), **CLI** (`logscope investigation …`), and **REST** (`/api/v1/investigations`).

## Added

### Domain (`scope_workspace`)

- `Investigation` aggregate root — UUID identity, manifest `schemaVersion: 1`
- `IArtifactHandler` — `log` and `note` types (extensible registry)
- Legacy `workspace.json` read migration

### Web (`logscope-web`)

- `InvestigationStore`, REST `/api/v1/investigations` (+ artifact routes)
- `investigationId` on `POST /api/v1/sessions/save`
- SPA **Investigations** panel (log upload + note form)
- `/api/v1/workspaces/*` delegates to same store (backward compatible)

### CLI

- `logscope investigation create|add|add-note|list|show|open`

## Unchanged / compat

- Existing workspace IDs and directories continue to work
- Analyze, investigate, tail, async jobs unchanged
- Entry artifact must be type `log` for open/analyze in v2.3.0 (Story 4 adds core/pstack)

## Out of scope (Story 2–4)

Multi-log correlation, unified timeline, crash analysis — deferred to `v2.4.0`–`v2.6.0`.

## Test baseline

- `scope_workspace_tests`, `scope_web_tests`, web integration/parity jobs green on CI
