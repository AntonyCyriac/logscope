# v2.2.0 — M15.3 Shared Investigations

## Highlights

- **Shared workspaces** — server-persisted named investigations (file-first JSON under `web.workspace_dir`)
- **Tail poll REST** — `POST /api/v1/tail/start|stop`, `GET /api/v1/tail/poll` for live log follow over HTTP
- **Async analyze** — large logs return `202 Accepted` + `GET /api/v1/jobs/{id}` poll; small logs stay synchronous
- **SPA W2** — shared workspace list/open/save, tail panel, async analyze progress in browser UI

## Added

- `WorkspaceStore` (`apps/web/workspace_store.{hpp,cpp}`) — CRUD, snapshot paths, UUID guards
- `AnalyzeJobQueue` — per-session async analyze jobs with TTL eviction
- REST: `POST/GET/PUT/DELETE /api/v1/workspaces`, `POST /api/v1/workspaces/{id}/open`
- REST: tail routes and job poll per [ADR-009-M15.3](../architecture/decisions/ADR-009-M15.3-Shared-Investigations.md)
- `POST /api/v1/sessions/save` accepts optional `workspaceId` to update shared snapshot
- Config keys: `web.workspace_dir`, `web.workspaces_list_limit`, `web.async_analyze_threshold_bytes`, `web.job_ttl_seconds`, `web.job_max_concurrent_per_session`
- **47** web-labelled tests green (unit + integration + CLI/REST parity)

## Changed

- Version **2.2.0** — M15.3 presentation-layer release
- `ApplicationService::pollTailLines` uses non-blocking `pollLine` when tailing file sources
- `WebServer::stop` drains HTTP listener before joining analyze worker threads

## Upgrade notes

**From release archive** (extract, run from that directory):

```bash
./logscope-web
# Open http://127.0.0.1:8080/
```

**From source:**

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DLOGSCOPE_WEB=ON
cmake --build build --target logscope-web
./build/apps/web/logscope-web
```

- Shared workspaces persist under `{data_dir}/workspaces` by default (override with `web.workspace_dir` / `LOGSCOPE_WEB_WORKSPACE_DIR`).
- Logs ≥ `web.async_analyze_threshold_bytes` (default 10 MiB) analyze asynchronously; poll `GET /api/v1/jobs/{jobId}` until `status: completed`.
- Default bind remains `127.0.0.1:8080`; set `web.api_key` before exposing on untrusted networks.

## Known limitations

- Playwright browser CI not included; W2 flows verified via manual REL.2 checklist
- `sourceRef.path` on workspace create is metadata-only; path validation on open when server paths enabled
- OpenAPI stub; full spec generation still optional follow-up
- Enterprise RBAC (M16) and API key hashing at rest beyond v2.2.1 thin auth
