# v2.9.1 — Timeline hotfix (#171, #172)

**Type:** Patch (post–`v2.9.0` timeline regressions)  
**Baseline:** `v2.9.0`  
**ADR:** [ADR-009-M15.9 Crash Timeline](../architecture/decisions/ADR-009-M15.9-Crash-Timeline.md) (timestamp amendment)

## Summary

Fixes two shipped-tag timeline issues from real-world investigations: **`crash.summary` placed at import time** instead of near incident logs ([#172](https://github.com/AntonyCyriac/logscope/issues/172)), and **silent omission** of log artifacts whose timestamps are not recognised ([#171](https://github.com/AntonyCyriac/logscope/issues/171)).

## Fixed

### [#172](https://github.com/AntonyCyriac/logscope/issues/172) — crash.summary timestamp

- Capture **`sourceModifiedAt`** (source file mtime) at artifact ingest; persist on manifest when available
- `crash.summary` timestamp resolver: **`sourceModifiedAt`** → `importedAt` fallback
- Event metadata: `timestampSource` (`source_mtime` | `imported_at`), `timestampApproximate: true`

### [#171](https://github.com/AntonyCyriac/logscope/issues/171) — silent log omission

- Per-artifact **`projectionStats`** (`linesRead`, `eventsEmitted`, `linesSkippedNoTimestamp`) on timeline projection
- **Warnings** when lines are skipped (e.g. unrecognised timestamp format)
- CLI table footer: source lines / timeline events / warnings / skipped lines
- REST/CLI JSON: `projectionStats` array alongside `warnings`
- **`investigation timeline --config`** — applies `analysis.plugin_format` (plugin registry) like `analyze` / `investigate`

## Upgrade notes

- **Re-import** pstack/core artifacts (or add new investigations) to populate `sourceModifiedAt` for better crash placement; existing manifests without the field still fall back to `importedAt`
- No `schemaVersion` bump — `sourceModifiedAt` is an optional artifact field
- Rebuild and redeploy from tag `v2.9.1`
