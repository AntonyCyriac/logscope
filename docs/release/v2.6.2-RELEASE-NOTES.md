# v2.6.2 — Signal-handler fault site hotfix (v2.6.1 follow-up)

**Type:** Patch  
**Baseline:** `v2.6.1`  
**Regression:** [#134](https://github.com/AntonyCyriac/logscope/issues/134)  
**Fix PR:** [#136](https://github.com/AntonyCyriac/logscope/pull/136)

## Summary

Fixes a **v2.6.1 follow-up** where `PstackCrashAnalyzer` could attribute the crash to a **signal-handler frame** (or pick a fault thread on **all-idle** pstack dumps) instead of the application frame below the handler boundary.

## Fixed

- **`crash_analyzer.cpp`** — preserve the signal-handler boundary; skip handler/runtime frames when choosing the fault site; do not mark a fault thread when every thread is parked idle

## Added (tests)

- `NamesFrameBelowSignalHandlerNotHandler` — fault site is the frame below `<signal handler called>`
- `NoFaultThreadWhenAllIdle` — no fault thread when all threads are idle waits

## Upgrade notes

No manifest, API, or config changes. Rebuild and redeploy `logscope`, `logscope-web`, and `logscope-desktop` from tag `v2.6.2`.
