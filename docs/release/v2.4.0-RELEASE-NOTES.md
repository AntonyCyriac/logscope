# v2.4.0 — Understand Everything (Story 2)

**Type:** Minor (Phase A — Story 2)  
**Baseline:** `v2.3.0`  
**ADR:** [ADR-009-M15.6 Multi-Source Investigation](../architecture/decisions/ADR-009-M15.6-Multi-Source-Investigation.md)

## Summary

Investigations now support **multiple artifact types** and **explicit log switching** within one incident folder. Engineers can collect app logs, syslog, stack traces (`pstack`), and core dumps (`core` — storage only) and switch which log is active for analyze/investigate without leaving the investigation.

## Story Gate demo

```text
Create → app log → syslog → pstack → list → switch syslog → investigate
```

Works via **web** (artifact list + Switch), **CLI** (`investigation add --type`, `open --artifact`), and **REST** (`POST .../open` with `artifactId`).

## Added

### Domain (`scope_workspace`)

- `PstackArtifactHandler`, `CoreArtifactHandler` (storage + metadata; no crash analysis)
- `artifactById`, `logArtifactDataPath(artifactId)`
- Optional `metadata.role` on ingest

### Web (`logscope-web`)

- `POST .../open` optional `artifactId`; response includes `loadedFromSnapshot`, `artifactType`
- Session `boundInvestigationId`, `activeArtifactId`
- Artifact list with `isEntry` in GET investigation
- SPA artifact list, log switch, pstack upload

### CLI

- `investigation add … [--type log|pstack|core] [--role <string>]`
- `investigation open … [--artifact <id>]`

## Unchanged / compat

- Manifest `schemaVersion: 1`
- `/api/v1/workspaces` alias preserved
- Snapshot restore only on entry/default open (not when switching logs)
- `core` artifacts stored only — analysis deferred to Story 4 (`v2.6.0`)

## Out of scope (Story 3–4)

Unified timeline (`v2.5.0`), cross-log correlation, crash analysis on `core` (`v2.6.0`).
