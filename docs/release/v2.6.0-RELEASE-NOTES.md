# v2.6.0 — Understand Why It Crashed (Story 4)

**Type:** Minor (Phase A — Story 4)  
**Baseline:** `v2.5.0`  
**ADR:** [ADR-009-M15.8 Crash Analysis](../architecture/decisions/ADR-009-M15.8-Crash-Analysis.md)

## Summary

Investigations now expose **structured crash evidence** by projecting `pstack` and `core` artifacts into a `CrashReport`. Engineers see signal, fault thread, stack frames, and factual observations — then jump from the Crash tab to the pstack view. Evidence only; no AI root cause.

## Story Gate demo

```text
Create investigation → Add app.log → Add pstack.txt
  → Analyze → Timeline (events + jump-to-source)
  → Crash tab → SIGSEGV + fault thread → Jump to pstack
  → Results populated after investigate
```

Works via **web** (IDE-style SPA + Playwright Story Gate), **CLI** (`investigation crash`), and **REST** (`GET .../crash-analysis`).

## Added

### Domain (`scope_workspace`)

- `CrashReport`, `CrashThread`, `IArtifactCrashAnalyzer`
- `PstackCrashAnalyzer` — parse gstack/pstack text (primary ship criterion)
- `CoreCrashAnalyzer` — GDB batch when on PATH; `unavailable` when absent
- `Investigation::analyzeCrash()` — on-demand projection (not persisted)

### Web (`logscope-web`)

- `GET /api/v1/investigations/{id}/artifacts/{artifactId}/crash-analysis`
- IDE-style SPA: artifacts left, center viewer, bottom dock (Timeline | Crash | AI | Results)
- Crash tab: signal card, fault-thread jump, pstack preview highlight
- Playwright Story Gate E2E (`tests/e2e/web/`) in CI Web Build Smoke

### CLI

- `investigation crash <id> [--artifact <artifactId>] [--format json|table]`

### Desktop

- Bottom tabs: Results | AI | Analytics (parity direction per UI architecture)

## Unchanged / compat

- Crash reports are **derived** — manifest `schemaVersion: 1` unchanged
- Timeline projection unchanged (no `crash.summary` events in v2.6.0)
- No correlation engine or ADR-010 domain events

## Out of scope (post–Story 4)

Timeline crash events, cross-log correlation, CrashScope product extraction.
