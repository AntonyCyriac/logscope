# v2.13.1 — Query Trust (Hardening Wave 2)

**Type:** Patch (trust / correctness — query semantics parity)  
**Baseline:** `v2.13.0`  
**ADR:** [ADR-005-M10.1 Query Trust](../architecture/decisions/ADR-005-M10.1-Query-Trust.md)

## Summary

`v2.13.1` ensures **query filters return the same evidence** whether evaluated in memory or through a persisted index. Silent false-empty results are eliminated for JSON ordered comparisons and CJK `contains()` with FTS5.

**Query Trust Gate (Wave 2):**

```text
#198: JSON field code > 10 — numeric compare (not silent zero)
#197: contains(message, "日本語") — FTS bypass; evaluator parity
```

**Binding principle:** the persisted index is an optimization, not a second query language.

## Fixed

### JSON field ordered comparisons ([#198](https://github.com/AntonyCyriac/logscope/issues/198))

- `>`, `<`, `>=`, `<=` on JSON numeric fields compare as numbers
- Non-numeric field values exclude the line (no match)
- String literal with ordered operator → explicit filter error (`validateFilterSemantics`)

### FTS `contains()` parity ([#197](https://github.com/AntonyCyriac/logscope/issues/197))

- `ftsContainsIsFaithful()` skips FTS5 pushdown for non-ASCII needles (e.g. CJK)
- Persisted-index path falls back to `QueryEvaluator` substring match — same count as in-memory
- ASCII `contains()` still uses FTS pushdown (regression unchanged)

## Changed

- `logscope query` / `investigate --filter` may reject filters such as `service > "PCF"` with a clear error (was exit 0 with zero matches)
