# v2.5.0 — See What Happened (Story 3)

**Type:** Minor (Phase A — Story 3)  
**Baseline:** `v2.4.1`  
**ADR:** [ADR-009-M15.7 Investigation Timeline](../architecture/decisions/ADR-009-M15.7-Investigation-Timeline.md)

## Summary

Investigations now expose a **chronological narrative** by **merging** (not correlating) **timeline events** projected from artifacts. Engineers see what happened across app logs, syslog, notes, and attached markers in one ordered view, then jump back to the source artifact (and log line on web).

## Story Gate demo

```text
Create investigation → Add app.log → Add syslog → Add note
  → Open timeline → See events in chronological order
  → Click event → Jump to source artifact
```

Works via **web** (Timeline panel), **CLI** (`investigation timeline`), and **REST** (`GET .../timeline`).

## Added

### Domain (`scope_workspace`)

- `TimelineEvent`, `IArtifactProjector`, `LogArtifactProjector`, `NoteArtifactProjector`, attached markers for `pstack`/`core`
- `Investigation::projectTimeline()` — merge, UTC sort, pagination, stable event `id` (FNV-1a)
- Undated log lines omitted from projection

### Web (`logscope-web`)

- `GET /api/v1/investigations/{id}/timeline` — `limit`, `offset`, `order=asc|desc`
- SPA **Timeline** panel with empty state, load-more, click-to-open log + line highlight in Results

### CLI

- `investigation timeline <id> [--format json|table] [--limit N] [--order asc|desc] [--dir <root>]`

## Unchanged / compat

- Timeline is a **read projection** — not authoritative; manifest unchanged
- No visual correlation or cross-artifact ID grouping
- M9 session `TimelineAnalyzer` remains separate (histogram on one log)

## Out of scope (Story 4)

Crash analysis on `core` (`v2.6.0`), cross-log correlation engine.
