# ADR-009 Amendment: M15.8 Crash Analysis (Story 4)

- **Status:** Accepted (amendment to ADR-009)
- **Date:** 06-08-2026
- **Parent ADR:** [ADR-009 Web Platform REST](ADR-009-Web-Platform-REST.md)
- **Release:** `v2.6.0` — Story 4: Understand Why It Crashed
- **Prior amendment:** [ADR-009-M15.7 Investigation Timeline](ADR-009-M15.7-Investigation-Timeline.md) (`v2.5.0`)

---

## Context

Stories 1–3 (`v2.3.0`–`v2.5.0`) let users **collect** artifacts, **switch** active logs, and **narrate** chronology. Engineers with `pstack` or `core` dumps still decode crashes manually. Story 4 delivers **structured crash evidence** by **projecting** analyzable artifacts into a `CrashReport`.

**Mission:** Understand why it crashed — evidence only, no AI root cause.

Constraints unchanged: Investigation aggregate owns truth; C10 `ApplicationService` unchanged; manifest `schemaVersion: 1`; file-first persistence; no timeline integration, correlation engine, or ADR-010 events in this release.

Story 3 timeline remains orthogonal. Crash analysis is a **separate projection** in v2.6.0.

---

## Decision

### 1. Crash analysis is a projection

Crash reports are **always derived**. Never authoritative storage.

```text
Investigation (authoritative)
    └── Artifacts
            └── IArtifactCrashAnalyzer (per type)
                    └── CrashReport (on demand)
```

| Layer | Persisted? |
|-------|------------|
| Artifact files (`pstack`, `core`) | **Yes** (Story 2) |
| `CrashReport` | **No** — computed per request |
| Optional `.crash-cache.json` | **Ephemeral** — invalidated when artifact data mtime/size changes |

Crash code references **`CrashReport` only** — not raw GDB sessions or LLM output.

### 2. CrashReport

Core domain object for crash evidence:

```cpp
struct CrashReport {
    std::string id;           // stable hash(investigationId, artifactId, analyzerVersion)
    std::string artifactId;
    std::string artifactType;
    CrashAnalysisStatus status;  // complete | partial | unavailable
    std::optional<std::string> signal;
    std::optional<std::string> faultThreadId;
    std::string summary;         // one-line factual summary
    std::vector<CrashThread> threads;
    std::vector<std::string> observations;  // evidence bullets — NOT root cause
    std::vector<std::string> warnings;
    std::map<std::string, std::string> metadata;
};
```

**No** `rootCause`, `confidence`, or LLM fields.

### 3. Artifact crash analyzers (open/closed)

```cpp
class IArtifactCrashAnalyzer {
public:
    virtual std::string_view artifactType() const noexcept = 0;
    virtual bool supports(const ArtifactRecord& artifact) const = 0;
    virtual bool canAnalyze(const ArtifactRecord& artifact,
                            const foundation::Path& dataPath) const = 0;
    virtual foundation::Result<CrashReport> analyze(
        const ArtifactRecord& artifact, const foundation::Path& dataPath,
        const CrashAnalysisContext& context) const = 0;
};
```

| Analyzer | Artifact type | v2.6.0 behavior |
|----------|---------------|-----------------|
| `PstackCrashAnalyzer` | `pstack` | **Required** — primary ship criterion; parse gstack/pstack text |
| `CoreCrashAnalyzer` | `core` | **Best effort** — GDB batch when on PATH; `unavailable` if absent |

New artifact types add an analyzer without changing `Investigation::analyzeCrash` routing.

### 4. GDB degradation (core)

| Condition | `status` | HTTP |
|-----------|----------|------|
| GDB on PATH, readable core | `complete` or `partial` | **200** |
| GDB missing | `unavailable` | **200** with `warnings[]` |
| GDB fails (corrupt core) | `partial` | **200** |
| No debug symbols | `partial` | **200** |

**Never** fail the investigation or return 500 solely because GDB is absent.

### 5. API (per-artifact)

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/v1/investigations/{id}/artifacts/{artifactId}/crash-analysis` | Returns **crash report** (domain JSON) |

| Code | When |
|------|------|
| 200 | Report returned (including `status=unavailable`) |
| 404 | Unknown investigation or artifact |
| 409 | `ARTIFACT_NOT_ANALYZABLE` (log, note) |

### 6. CLI parity

```text
investigation crash <id> [--artifact <artifact-id>] [--format json|table] [--dir <root>]
```

Default artifact: first `pstack` or `core` in manifest when `--artifact` omitted.

### 7. Manifest

**No schema bump.** Crash reports are not stored in `manifest.json`.

### 8. Out of scope (Story 4)

- Timeline integration (`crash.summary` events)
- AI root cause / confidence labels
- Correlation engine
- Interactive GDB
- ADR-010 domain events
- SPA panel (deferred unless quick follow-up)

---

## Consequences

- **Positive:** Structured crash evidence from pstack/core; extensible analyzer registry; per-artifact REST matches artifact-centric model; GDB optional without breaking deployments.
- **Negative:** Core analysis quality depends on host GDB and symbols; pstack dialect coverage is MVP-only.
- **Neutral:** Story 1–3 investigations unchanged; timeline projection unchanged in v2.6.0.
