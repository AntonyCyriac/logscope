## Context

Story 3 (`v2.5.0`) projects log and attachment events onto the investigation **timeline**. Story 4 (`v2.6.0`) projects **CrashReport** evidence on demand via the Crash tab and REST/CLI — explicitly **without** timeline integration.

Today, `pstack` and `core` artifacts appear on the timeline only as **`artifact.attached`** at import time. Engineers must switch to the Crash tab to see analyzed crash evidence and cannot place the crash in chronological context with log events or link crash nodes via Story 5/6 without a dedicated timeline event.

**Mission:** See the crash in the incident timeline.

> **P1 makes existing crash analysis visible in the investigation timeline; it does not make crash analysis smarter.**

**Binding principles:**

- **Projection only** — `crash.summary` consumes existing `CrashReport`; no analyzer, parser, or GDB changes.
- **No manifest change** — `schemaVersion` unchanged; crash reports remain ephemeral.
- **Story 4 frozen** — timeline code calls `analyzeCrash` only; it does not enrich or reinterpret analysis.
- **#144 deferred** — alternate pstack dialects and plugin registry are out of `v2.9.0`.

---

## Decision

### 1. `crash.summary` TimelineEvent

Timeline projection gains a second phase — **CrashSummaryEnricher** — after artifact projectors:

```text
Investigation (authoritative)
    └── Artifacts
            ├── IArtifactProjector (log, note, …)
            └── analyzeCrash() → CrashReport (Story 4 — unchanged)
                    └── CrashSummaryEnricher → crash.summary TimelineEvent[]
```

| Field | Value |
|-------|-------|
| `eventType` | **`crash.summary`** |
| `id` | `makeTimelineEventId(investigationId, artifactId, 0, timestamp, "crash.summary")` |
| `timestamp` | `artifact.importedAt` (v2.9.0 — Story 4 does not expose crash instant) |
| `message` | From `CrashReport.summary` when `ready`; degraded message when `unavailable` / `failed` |
| `metadata` | `crashReportId`, `status`, optional `signal`, `faultThreadId` |

**Binding rule:** `crash.summary` exposes only information already available from the existing `CrashReport`; P1 does not enrich or reinterpret crash analysis. **`EventSource.lineNumber` is not set** in v2.9.0 (no fault-frame line ref).

### 2. Replace `artifact.attached` for pstack/core

**Only** artifact types **`pstack`** and **`core`** that participate in Crash Timeline projection **stop emitting** `artifact.attached`. They emit **`crash.summary`** instead (including when analysis is `unavailable` or `failed`).

All other artifact types retain existing `artifact.attached` behavior.

```text
Before:  artifact.attached → (separate) Crash tab analysis
After:   crash.summary      → jump to Crash evidence
```

### 3. Multiple crash artifacts

- **One artifact → at most one `crash.summary`** per timeline projection.
- **N pstack/core artifacts → up to N events**, merged into global chronological sort with log events.
- Tie-break at equal timestamp: lexicographic `artifactId` (unchanged Story 3 rule).

### 4. Analysis status → emit behavior

| `CrashAnalysisStatus` | Emit `crash.summary`? |
|----------------------|------------------------|
| `ready` | Yes — full summary |
| `unavailable` | Yes — degraded row |
| `failed` | Yes — degraded row |
| `not_supported` | No |

### 5. Surfaces

| Surface | Change |
|---------|--------|
| `GET …/timeline` | Includes `crash.summary` in `events[]` |
| CLI `investigation timeline` | Same event stream |
| Web Timeline | Distinct crash row; select → Crash tab for artifact |
| Story 5 evidence links | Crash event ids valid as endpoints — no API change |
| Story 6 suggestions | Unchanged engine |

### 6. Out of scope (`v2.9.0`)

- Story 4 analyzer / parser / GDB improvements ([#144](https://github.com/AntonyCyriac/logscope/issues/144))
- Parsed crash timestamp (until Story 4 exposes it)
- Manifest schema bump
- Persisted crash reports
- Desktop Timeline parity (P2)
- AI root cause
- Correlation engine changes

---

## Consequences

- **Positive:** Crash evidence appears in chronological narrative; Story 5/6 can anchor links to crash nodes; small, reviewable release.
- **Negative:** Timeline GET may invoke `analyzeCrash` per pstack/core artifact (same order as opening Crash tab per artifact).
- **Neutral:** V260 NG.1 inverted — timeline **may** include `crash.summary`; Story 4 crash-analysis tests unchanged.
