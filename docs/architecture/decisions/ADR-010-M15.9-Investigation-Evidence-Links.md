# ADR-010: M15.9 Investigation Evidence Links (Story 5)

- **Status:** Accepted
- **Date:** 06-08-2026
- **Parent ADR:** [ADR-009 Web Platform REST](ADR-009-Web-Platform-REST.md)
- **Release:** `v2.7.0` — Story 5: Connect the Evidence
- **Prior amendment:** [ADR-009-M15.8 Crash Analysis](ADR-009-M15.8-Crash-Analysis.md) (`v2.6.0`)

---

## Context

Stories 1–4 (`v2.3.0`–`v2.6.1`) let users **collect** artifacts, **inventory** evidence, **narrate** chronology, and **project** crash reports. Engineers still connect related timeline events mentally. Story 5 answers **how is it connected** by letting investigators **record and navigate** relationships between timeline events.

**Mission:** Connect evidence across an investigation so engineers see relationships, not isolated artifacts.

**Principles (binding):**

- **Evidence Links are assertions made by the investigator, not facts inferred by the system.**
- **Evidence Links are immutable historical observations** — no in-place edit; remove and create anew if the investigator changes their mind.
- Relationships are evidence, not conclusions (`RELATED` ≠ causation).

Constraints: Investigation aggregate owns truth; C10 `ApplicationService` unchanged; manual links only in P0.1; four link types frozen; user-facing **Related Evidence** / **Connections** vocabulary; no Correlation view in P0.1.

Story 3 timeline and Story 4 crash projections remain orthogonal. Evidence Links are **persisted** in the investigation manifest, not derived.

---

## Decision

### 1. Evidence Links are persisted investigation evidence

```text
Investigation (authoritative)
    ├── Artifacts (evidence files)
    ├── evidenceLinks[] (relationship evidence)     ← Story 5 — persisted
    └── Timeline (projection from artifacts)        ← Story 3 — anchor surface only
```

| Layer | Persisted? |
|-------|------------|
| Investigation manifest + artifact files | **Yes** |
| `evidenceLinks[]` | **Yes** — manifest `schemaVersion: 2` |
| `TimelineEvent` stream | **No** — computed on demand |
| Link `status` (active/stale) | **No** — computed at list time |

Timeline code **never** writes links. Link endpoints reference `TimelineEvent.id` for navigation — timeline events are not domain entities.

### 2. Manifest schema v2

Bump `schemaVersion` from `1` → `2`. Add `evidenceLinks[]` to `manifest.json`. **No sidecar file.**

**Lazy migration:** v1 manifests read as `evidenceLinks: []`. Bump to v2 only on first link write — not on no-op save.

```json
{
  "schemaVersion": 2,
  "evidenceLinks": [
    {
      "id": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
      "type": "RELATED",
      "source": { "kind": "timeline_event", "eventId": "a1b2..." },
      "target": { "kind": "timeline_event", "eventId": "f6e5..." },
      "createdAt": "2026-08-06T12:00:00Z",
      "note": "optional investigator note"
    }
  ]
}
```

**Not stored:** confidence, causation, auto-rule id, correlation key, `status`.

### 3. Link types (frozen v2.7.0)

All types are **directed** (`source` → `target`):

| Type | Semantics |
|------|-----------|
| `PRECEDES` | Source precedes target in narrative |
| `FOLLOWS` | Source follows target |
| `SUPPORTS` | Source supports target (not root cause) |
| `RELATED` | Source related to target (not causation) |

`RELATED` A→B and `RELATED` B→A are **separate investigator assertions** — do not normalize, deduplicate, or treat as symmetric.

### 4. Anchors: TimelineEvent.id only (v2.7.0)

Both endpoints use `{ kind: "timeline_event", eventId }` referencing Story 3 deterministic `makeTimelineEventId`. Artifact-only or crash-frame anchors deferred.

### 5. Validation and stale links

| Operation | Rule |
|-----------|------|
| **Create** | Both `eventId` values must exist in **full** timeline projection |
| **List** | Annotate each link with computed `status`: `active` or `stale` |
| **Stale** | Persist link; never auto-delete when projection changes |

UI copy for missing endpoints: **"Event unavailable"**.

Investigations are historical records — relationships must not silently disappear when artifacts change.

### 6. Duplicates and immutability

| Rule | Behavior |
|------|----------|
| Duplicate `(source.eventId, target.eventId, type)` | **409** `DUPLICATE_EVIDENCE_LINK` |
| Edit existing link | **Not supported** — `DELETE` + `POST` new link |
| HTTP verbs | `GET`, `POST`, `DELETE` only on `/evidence-links` |

### 7. API

Base: `/api/v1/investigations/{investigationId}`

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/evidence-links` | List links with computed `status` |
| `POST` | `/evidence-links` | Create link (manual investigator assertion) |
| `DELETE` | `/evidence-links/{linkId}` | Remove link |

**`GET /timeline` unchanged.** Web client fetches evidence links separately and merges for row decorations and **Related Evidence** panel.

| Code | When |
|------|------|
| 200 | Success |
| 201 | Link created |
| 400 | `INVALID_LINK_TARGET` — event id not in projection |
| 404 | Unknown investigation or link |
| 409 | `DUPLICATE_EVIDENCE_LINK` |

### 8. CLI parity

```text
investigation links list <id> [--format json|table] [--dir <root>]
investigation links add <id> --source <event-id> --target <event-id> --type RELATED [--note "..."]
investigation links remove <id> --link <link-id> [--dir <root>]
```

### 9. Web UI contract (P0.1)

- Connection badge on timeline rows with links (`Related (n)`)
- **Related Evidence** panel on event selection
- Click linked entry → jump/scroll/highlight target event
- No graph view, no correlation lines, no user-facing "Correlation" language

### 10. Out of scope (Story 5 P0.1)

- Evidence Groups (P0.2)
- Correlation View (P0.3)
- Auto heuristics / AI-suggested links
- Linkable artifacts or crash frames without timeline events
- Desktop timeline link parity (P2)
- `PUT`/`PATCH` on links

---

## Consequences

- **Positive:** Third north-star pillar (connect) without redesigning Investigation, Artifacts, or Timeline; export/import carries relationships; clean separation of projection vs persisted evidence; foundation for future Intelligence-era link suggestions (human acceptance required).
- **Negative:** Client must merge two API responses for rich timeline UI; stale links require UX for unavailable events.
- **Neutral:** Story 1–4 investigations unchanged until first link write; timeline projection algorithm unchanged.
