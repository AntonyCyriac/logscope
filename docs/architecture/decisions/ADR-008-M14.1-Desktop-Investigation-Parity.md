## Context

M14 (`v2.0.0`) delivered `logscope-desktop` as a **session workbench** over `ApplicationService` — open log, analyze, investigate, AI, analytics. M15 Stories 1–6 and P1 shipped the **investigation container workflow** on web first: artifacts, timeline projection, crash analysis, evidence links, and correlation suggestions.

Desktop bottom tabs today: **Results · AI · Analytics**. Web bottom dock: **Timeline · Crash · AI · Results**. The gap is documented in `tests/e2e/web/README.md`.

**Mission:** Same investigation mental model on desktop — without a redesign and without new investigation capabilities.

> **P2 puts Timeline and Crash on the Qt shell; it does not port every web affordance.**

**Binding principles:**

- **Consume contracts** — `workspace::Investigation::projectTimeline()` and `analyzeCrash()` only; no desktop domain models.
- **Render only** — Qt panels display `TimelineProjectionResult` and `CrashReport`; no projection or analyzer changes.
- **Stories 3–6 + P1 frozen** — desktop displays existing event types including `crash.summary`.
- **Story 5/6 interactive UI deferred** — Related Evidence and Suggestions chrome tracked as P2.1 follow-up.

---

## Decision

### 1. Investigation mode on desktop

`MainWindow` gains **Investigation mode** alongside existing **Session mode**:

| Mode | Entry | Purpose |
|------|-------|---------|
| Session | Default | Existing M14 workflows (unchanged) |
| Investigation | Investigation → New / Open | Host Timeline + Crash tabs |

Minimum chrome: create/open/close investigation, artifact list, add log/pstack file. Portable investigation directories — same layout as CLI/REST.

### 2. `InvestigationController` (`apps/common/`)

Thin façade over `workspace::Investigation`:

```text
InvestigationController
    └── workspace::Investigation (create / open / persist)
            ├── projectTimeline() → TimelineProjectionResult
            └── analyzeCrash(artifactId) → CrashReport
```

Not a domain model — delegates all mutations to core. `ApplicationService` remains responsible for log `openSource` / `analyze` / `investigate` when a log artifact is active.

**Rejected:** Desktop-specific investigation structs; HTTP calls to local REST server.

### 3. Bottom dock tabs

Extend `QTabWidget`:

```text
Timeline | Crash | Results | AI | Analytics
```

- **Timeline** and **Crash** disabled when no investigation is open.
- Tab labels match web for Timeline and Crash.
- Results/AI order differs from web (desktop history); Timeline/Crash lead for investigation narrative parity.

### 4. Panels

| Tab | Widget | Data |
|-----|--------|------|
| Timeline | `TimelinePanel` | `projectTimeline()` — all `eventType` values including `crash.summary` |
| Crash | `CrashPanel` | `analyzeCrash()` — signal, threads, embedded pstack viewer |

Long-running projection/analysis on `QThread` workers; UI updates on main thread.

### 5. Navigation (jump protocol)

Presentation-only `ViewerNavigation` in `MainWindow`:

| Source | Target |
|--------|--------|
| Timeline `log.line` | Results tab + line highlight via `ApplicationService` |
| Timeline `crash.summary` | Crash tab + load pstack artifact |
| Crash fault-thread click | Highlight thread block in Crash pstack viewer |

No new three-pane center viewer in v2.11.0 — log evidence in Results table; pstack evidence in Crash tab viewer.

### 6. Story 5 / Story 6 scope (explicit)

| Surface | v2.11.0 |
|---------|---------|
| Related Evidence panel | **Out** — P2.1 follow-up |
| Link badges / create-link UI | **Out** — P2.1 follow-up |
| Correlation suggestions UI | **Out** — P2.1 follow-up |

`listEvidenceLinks()` may be called read-only for optional badge stretch — non-blocking.

---

## Consequences

### Positive

- Closes documented web ↔ desktop parity gap for Timeline + Crash.
- Reuses proven investigation container from Stories 1–6.
- Session-mode desktop users unaffected.
- Clear follow-up boundary (P2.1) prevents scope creep.

### Negative

- `InvestigationController` parallels `InvestigationStore` until a future consolidation.
- Investigation mode UI is minimal — not a full SPA port.
- Tab order differs slightly from web for Results/AI.
- **Synchronous Timeline/Crash refresh** on the UI thread in v2.11.0 — performance follow-up only; not a domain-contract change (see [V211-DESKTOP-PARITY-SCENARIOS.md](../../planning/V211-DESKTOP-PARITY-SCENARIOS.md) § Known limitation).
