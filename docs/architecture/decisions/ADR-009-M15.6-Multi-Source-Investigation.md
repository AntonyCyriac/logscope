# ADR-009 Amendment: M15.6 Multi-Source Investigation (Story 2)

- **Status:** Accepted (amendment to ADR-009)
- **Date:** 05-08-2026
- **Parent ADR:** [ADR-009 Web Platform REST](ADR-009-Web-Platform-REST.md)
- **Release:** `v2.4.0` — Story 2: Understand Everything
- **Prior amendment:** [ADR-009-M15.5 Investigation Container](ADR-009-M15.5-Investigation-Container.md) (`v2.3.0`)

---

## Context

Story 1 (`v2.3.0`) introduced portable **Investigations** with multiple artifacts, but `POST .../open` always loaded the **entry artifact** (`primaryArtifactId`). Engineers collecting app logs, syslog, notes, and stack traces need to **see all artifacts** and **switch the active log** for analyze/investigate without leaving the investigation.

Constraints unchanged: C12 thin handlers over **ApplicationService**; one active source per session; file-first persistence; manifest `schemaVersion: 1`; no timeline, correlation, or crash analysis in this release.

---

## Decision

### 1. Entry vs active artifact

| Concept | Storage | Meaning |
|---------|---------|---------|
| **Entry artifact** | `manifest.primaryArtifactId` | Default log when `artifactId` omitted on open |
| **Active artifact** | `WorkspaceSession.activeArtifactId` | Log currently loaded in `ApplicationService` |

Active artifact is **session-scoped**, not persisted in the manifest.

### 2. Open semantics

| Request | Behavior |
|---------|----------|
| No `artifactId` | Entry log; snapshot allowed when present |
| `artifactId` = entry log | Same as above |
| `artifactId` = other log | **Never** load snapshot; `openSource` for that log only |
| `artifactId` = note/pstack/core | **409** `ARTIFACT_NOT_OPENABLE` |

### 3. New artifact types (storage only)

| Type | Handler | Session open? |
|------|---------|---------------|
| `pstack` | `PstackArtifactHandler` | No — text copy |
| `core` | `CoreArtifactHandler` | No — binary copy + `metadata.sizeBytes` |

`core` is **store + metadata only** in `v2.4.0` — no GDB or crash analysis (Story 4).

Optional `metadata.role` (string) on ingest via REST/CLI `role` field.

### 4. API changes

- `POST /api/v1/investigations/{id}/open` — optional body `{ "artifactId": "uuid" }`; response includes `artifactId`, `artifactType`, `loadedFromSnapshot`
- `POST .../artifacts` — accepts `log`, `note`, `pstack`, `core`; optional `role`
- `GET .../investigations/{id}` — artifacts include `metadata`, `isEntry`
- `/api/v1/workspaces` alias **unchanged** through `v2.4.x`

### 5. CLI parity

```text
investigation add <id> <file> [--type log|pstack|core] [--role <string>]
investigation open <id> [--artifact <uuid>]
```

### 6. Out of scope (Story 2)

- Unified timeline (Story 3)
- Cross-log correlation (Story 3+)
- Crash analysis on `core` (Story 4)
- Manifest schema v2

---

## Consequences

- **Positive:** Multi-log incident workflow; explicit switch without corrupting snapshot semantics; extensible artifact index for SPA/CLI.
- **Negative:** Session binding adds state; clients must pass `artifactId` to switch logs.
- **Neutral:** Story 1 investigations remain valid; first `log` artifact still becomes entry artifact.
