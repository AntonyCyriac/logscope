# ADR-009 Amendment: M15.3 Shared Investigations

- **Status:** Accepted (amendment to ADR-009)
- **Date:** 31-07-2026
- **Parent ADR:** [ADR-009 Web Platform REST](ADR-009-Web-Platform-REST.md)
- **Milestone:** M15.3 — `v2.2.0`
- **Design contract:** `logscope-strategy/engos/artifacts/M15.3/design.md` (private; summarized below)

---

## Context

ADR-009 §3 listed tail routes and §8 noted async analyze as M15.3 options. `v2.1.0` shipped without tail handlers, synchronous-only analyze, and in-memory sessions. M15.3 closes three deferrals: **shared workspaces**, **tail poll**, and **async analyze jobs**, plus SPA wiring.

Constraints unchanged: C12 thin handlers over **ApplicationService**; offline single process; CLI parity gates; file-first persistence (SQLite deferred to M16).

---

## Decision

### 1. New REST routes

| Method | Path | ApplicationService / C12 store | Purpose |
|--------|------|----------------------------------|---------|
| `POST` | `/api/v1/workspaces` | `WorkspaceStore::create` (+ optional `saveSession`) | Create shared workspace |
| `GET` | `/api/v1/workspaces` | `WorkspaceStore::list` | List workspace metadata (bounded) |
| `GET` | `/api/v1/workspaces/{id}` | `WorkspaceStore::getMetadata` | Metadata + summary (no session adopt) |
| `PUT` | `/api/v1/workspaces/{id}` | `WorkspaceStore::updateMetadata` | Update name/description |
| `DELETE` | `/api/v1/workspaces/{id}` | `WorkspaceStore::remove` | Delete workspace + snapshots |
| `POST` | `/api/v1/workspaces/{id}/open` | `loadSession` + `adoptModel` | Open into `X-LogScope-Session` workspace |
| `POST` | `/api/v1/tail/start` | `startTail` | Begin live tail on open file source |
| `POST` | `/api/v1/tail/stop` | `stopTail` | Stop tail |
| `GET` | `/api/v1/tail/poll` | `pollTailLines` | Non-blocking appended lines |
| `GET` | `/api/v1/jobs/{id}` | `AnalyzeJobQueue` (C12g) | Poll async analyze job status/result |

**Changed route:**

| Method | Path | Change |
|--------|------|--------|
| `POST` | `/api/v1/analyze` | When source size ≥ `web.async_analyze_threshold_bytes`, return **`202 Accepted`** with `jobId` and `Location: /api/v1/jobs/{id}`; otherwise unchanged synchronous `200` |
| `POST` | `/api/v1/sessions/save` | Optional body field `workspaceId` — saves snapshot to shared workspace path |

All routes require `X-LogScope-Session` except `health` and `POST /api/v1/sessions/workspace`. Optional API key middleware applies when `web.api_key` is set.

### 2. Async analyze (`202`) behavior

1. Handler probes opened source file size via session's `sourcePath()`.
2. Below `web.async_analyze_threshold_bytes` (default 10 MiB): synchronous `analyze()` → `200` + `AnalysisModel` summary JSON (backward compatible).
3. At or above threshold: enqueue job on session-scoped `AnalyzeJobQueue`, return:

```http
HTTP/1.1 202 Accepted
Location: /api/v1/jobs/{jobId}
```

```json
{
  "data": {
    "jobId": "uuid",
    "status": "running",
    "pollUrl": "/api/v1/jobs/uuid"
  }
}
```

4. `GET /api/v1/jobs/{id}` returns `running` | `completed` | `failed`. Completed payload includes analyze summary matching sync/CLI JSON. Failed includes error details. Jobs are visible only to the creating session. TTL: `web.job_ttl_seconds` (default 3600).

### 3. Tail poll semantics

- Matches desktop `TailWorker` → `ApplicationService::pollTailLines()` (batch up to 64 lines per poll).
- `POST /tail/start` when already tailing → `409 InvalidState`.
- `GET /tail/poll` when tail inactive → `409 InvalidState` (explicit state machine; not empty `200`).
- Poll-first only; WebSocket push remains post-MVP.

### 4. File-first shared workspace persistence

**Configuration:** `web.workspace_dir` (default `{data_dir}/workspaces`), `web.workspaces_list_limit` (default 100).

**Layout:**

```text
{web.workspace_dir}/{workspace-uuid}/
  workspace.json      # metadata + summary + sourceRef
  snapshot.session    # InvestigationSession file (existing workspace::SessionStore format)
```

**`workspace.json` (high level):**

```json
{
  "schemaVersion": 1,
  "id": "uuid",
  "name": "string",
  "description": "string",
  "createdAt": "ISO-8601",
  "updatedAt": "ISO-8601",
  "sourceRef": {
    "type": "upload | server_path",
    "displayName": "string",
    "path": "optional server path"
  },
  "summary": {
    "hasModel": true,
    "lineCount": 0,
    "errorCount": 0
  },
  "snapshotFile": "snapshot.session"
}
```

**Safety:** Workspace ids are UUIDs only; all paths canonicalized under `web.workspace_dir`; traversal rejected; `sourceRef.path` subject to `web.allowed_path_roots` when server paths enabled.

**SQLite:** Deferred to M16 for multi-user index/ACL; v2.2.0 uses directory scan. `schemaVersion` supports future migration.

### 5. Session and isolation model

| Concern | Rule |
|---------|------|
| Shared workspace files | Global under `workspace_dir`; any client may list/get metadata |
| Active investigation state | Per `X-LogScope-Session` only; `open` loads snapshot into caller session |
| Analyze jobs | Scoped to creating session; cross-session poll → 403/404 |
| Tail state | Per session |

### 6. New configuration keys

| Key | Default | Purpose |
|-----|---------|---------|
| `web.workspace_dir` | `{data_dir}/workspaces` | Shared workspace storage root |
| `web.workspaces_list_limit` | `100` | Max workspaces in list response |
| `web.async_analyze_threshold_bytes` | `10485760` | Async analyze threshold |
| `web.job_ttl_seconds` | `3600` | Job record TTL |
| `web.job_max_concurrent_per_session` | `1` | Max in-flight analyze jobs per session |

### 7. Test and release gates

Scenario matrix: [M15-V220-SHARED-INVESTIGATIONS-SCENARIOS.md](../../planning/M15-V220-SHARED-INVESTIGATIONS-SCENARIOS.md). CI `web` job must pass SW1, T1, J1, S2, P1 API rows before `v2.2.0` tag. Release regression policy per ADR-009 §10.6 / RELEASE.md §8.

## Consequences

### Positive

- Activates ADR-009 tail and async analyze placeholders without new presentation layer.
- File-first workspaces ship collaboration without DB operational burden.
- Threshold-based analyze preserves v2.1.0 sync client behavior for small logs.

### Negative

- Global workspace directory requires filesystem backup discipline on shared hosts.
- Directory list may slow with many workspaces until SQLite lands in M16.
- Detached analyze threads add operational complexity vs sync-only v2.1.0.
