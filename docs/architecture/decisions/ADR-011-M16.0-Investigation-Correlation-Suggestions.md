# ADR-011: M16.0 Investigation Correlation Suggestions (Story 6)

- **Status:** Accepted
- **Date:** 12-08-2026
- **Parent ADR:** [ADR-010 Investigation Evidence Links](ADR-010-M15.9-Investigation-Evidence-Links.md)
- **Release:** `v2.8.0` — Story 6: Discover the Connections
- **Prior release:** [v2.7.1](../../release/v2.7.1-RELEASE-NOTES.md) — Story 5 manual evidence links

---

## Context

Story 5 (`v2.7.0`) lets investigators **record** relationships between timeline events via persisted **Evidence Links**. Engineers still hunt shared identifiers (`request_id`, `trace_id`, etc.) across artifacts manually.

Story 6 answers **what might be connected** by proposing **Correlation Suggestions** — ephemeral candidates the engineer reviews and either **accepts** (→ `EvidenceLink`) or **dismisses** (no manifest write).

**Mission:** Find plausible cross-artifact connections, explain why, let the engineer decide.

**Binding principles:**

- **Suggestions are proposals; only accepted links are evidence.**
- **No path from suggestion → manifest without explicit accept** via Story 5 `addEvidenceLink`.
- **Key match ≠ causality** — exact key equality means "may belong to same request," not "A caused B."
- **User-facing vocabulary:** **Suggested connections** / Related Evidence / Connections — never "Correlation" in UI copy. Internal code may use `CorrelationEngine`, `CorrelationSuggestion`.

Constraints: exact-key v1 only; ±30s proximity is a filter, never sole criterion; Timeline surface only (not Correlation View); no fuzzy matching, AI, or graph UI in v2.8.0.

---

## Decision

### 1. Ephemeral suggestions vs persisted links

```text
Timeline projection
       ↓
CorrelationEngine → CorrelationSuggestion[]   (ephemeral)
       ↓ accept                          ↓ dismiss
EvidenceLink (manifest)              session.dismissedSuggestionIds
```

| Layer | Persisted? |
|-------|------------|
| `evidenceLinks[]` | **Yes** — Story 5 manifest v2 |
| `CorrelationSuggestion` | **No** — computed on demand |
| `dismissedSuggestionIds` | **No** — web/session store only, not Investigation aggregate |
| Suggestion cache | **No** — optional session optimization |

### 2. Correlation keys (v1)

Exact match on five keys (structured fields first, regex fallback on message):

- `request_id`
- `trace_id`
- `session_id`
- `transaction_id`
- `correlation_id`

**Proximity filter:** when both events have parseable timestamps, `|timeDeltaMs| ≤ 30000` required. Missing timestamp → key match still valid; proximity skipped for that pair.

**Cross-artifact only:** suggestions emitted only when `source.artifactId ≠ target.artifactId`.

### 3. Explainability (required)

Every `CorrelationSuggestion` includes:

| Field | Purpose |
|-------|---------|
| `matchedKey`, `matchedValue` | Basis for the suggestion |
| `sourceArtifactName`, `targetArtifactName` | Where matched |
| `sourceLineRef`, `targetLineRef` | Optional line refs |
| `timeDeltaMs` | Signed delta when timestamps available |
| `ruleId` | e.g. `exact_key_match` |
| `summary` | Human-readable one-liner |

### 4. Pair-level dedup

**Before accept:** same undirected event pair may appear as multiple suggestions (different keys).

**After accept:** once **any** `EvidenceLink` exists between events A and B (either direction, any type), **all** suggestions for that pair are suppressed — prevents accept → `409 DUPLICATE_EVIDENCE_LINK` on a sibling-key suggestion.

### 5. Accept and dismiss

- **Accept:** `POST .../correlation-suggestions/{id}/accept` → `addEvidenceLink()` with default type `RELATED` (optional override).
- **Dismiss:** `POST .../correlation-suggestions/{id}/dismiss` → session dismiss set only.
- **Caps:** 50 suggestions per event involvement; 500 per investigation; paginated list API.

### 6. TimelineEvent ID stability

Suggestion IDs hash `investigationId`, undirected event pair, and `matchedKey`. Event IDs come from Story 3:

```text
hash(investigationId | artifactId | sequence | timestampIso | eventType)
```

Stable when projection inputs are unchanged. Reparse/format changes may produce new event IDs — suggestions recompute; **no new persistent event identity in v2.8.0**.

### 7. Surfaces

| Surface | Operations |
|---------|------------|
| REST | `GET/POST` correlation-suggestions, accept, dismiss |
| CLI | `investigation suggestions list|accept|dismiss` |
| Web | Timeline **Suggested connections** panel with basis display |

---

## Consequences

### Positive

- Extends Story 5 without violating trust model
- Explainable, testable, no AI dependency
- Boring exact-key v1 is shippable and earns smarter engine later

### Negative / limits

- No same-artifact suggestions in v1
- Hot keys in large logs hit caps (`truncated: true`)
- Dismiss state lost on session reload (intentional)

---

## Out of scope (v2.8.0)

- Correlation View / graph UI (P0.3)
- Evidence Groups (P0.2)
- Fuzzy matching, semantic similarity
- AI-suggested links (P5)
- Persisted dismiss list
- Cross-investigation suggestions
