# ADR-009 Amendment: M15.4 Thin Auth

- **Status:** Accepted (amendment to ADR-009)
- **Date:** 31-07-2026
- **Parent ADR:** [ADR-009 Web Platform REST](ADR-009-Web-Platform-REST.md)
- **Milestone:** M15.4 — `v2.2.1`
- **Design contract:** `logscope-strategy/engos/artifacts/M15.4/design.md` (private; summarized below)

---

## Context

M15.3 (`v2.2.0`) shipped shared workspaces, tail poll, and async analyze on the existing optional single API key and in-memory `SessionStore`. ADR-009 §5 deferred **thin auth** hardening: session TTL, upload temp cleanup, explicit health probe policy, and deployment guidance for non-loopback binds.

M15.4 closes that deferral as a **PATCH** release — no new REST routes, no RBAC (M16).

---

## Decision

### 1. Session idle TTL and eviction

| Key | Default | Behavior |
|-----|---------|----------|
| `web.session_ttl_seconds` | `0` | When `> 0`, evict sessions with no activity for this duration. `0` disables eviction (v2.2.0 behavior). |
| `web.max_sessions` | `0` | When `> 0`, cap in-memory sessions; evict oldest idle sessions before create; `503` if limit still exceeded. |

**Activity:** `lastActivityAt` updated on successful session resolve (existing id). Eviction skips sessions with a **running** async analyze job (`AnalyzeJobQueue::hasRunningJobForSession`).

**On evict:** Stop tail if active, delete staged upload temp (`tempUploadPath`), remove session from `SessionStore`.

**Sweep:** `evictIdleSessions` invoked from `GET /api/v1/health` (when TTL enabled) and `POST /api/v1/sessions/workspace`.

**Stale session:** Request with `X-LogScope-Session` referencing an evicted or unknown id → **401** with `SESSION_EXPIRED` (mutating routes). Empty/missing session without auto-create remains **400**.

### 2. Upload temp cleanup

Staged multipart uploads set `WorkspaceSession::tempUploadPath`. M15.4 requires:

- Delete superseded temp file on new upload (`replaceStagedUpload`).
- Delete temp on server-path open when replacing an upload-backed source.
- Delete temp on session evict and (recommended) graceful server shutdown.

Cleanup runs under the per-session mutex with `ApplicationService` mutations.

### 3. API key and health policy

| Key | Default | Behavior |
|-----|---------|----------|
| `web.api_key` | empty | Unchanged — when set, `X-LogScope-Api-Key` required on mutating `/api/v1/*` routes. |
| `web.health_requires_api_key` | `false` | When `true` **and** `api_key` set, `GET /api/v1/health` requires the key. Default preserves ADR-009: health may remain open for probes. |

Plain string compare for API key in **v2.2.1**; hashing at rest planned for **`v2.2.2`** (security patch).

### 4. Bind exposure warning

When `web.bind_host` is not loopback (`127.0.0.1`, `::1`, `localhost`) and `web.api_key` is empty, `logscope-web` logs a **WARNING** at startup. Process does not exit (operators may terminate TLS at a reverse proxy).

### 5. Routes

**No new routes.** Changed behavior only on:

- `GET /api/v1/health` — optional key per §3
- `POST /api/v1/sessions/workspace` — max session enforcement
- Session-scoped routes — stale session 401 per §1

M15.3 routes (workspaces, tail, jobs) remain behind `authorizeApiKey` when key configured — regression tests only.

## Consequences

### Positive

- Predictable memory and disk use on shared hosts
- Testable auth boundary for health and stale sessions
- Backward compatible defaults

### Negative

- Idle TTL may surprise long-paused browser tabs (document TTL in handbook)
- Temp cleanup deletes files the SPA no longer references — expected for staged uploads only
