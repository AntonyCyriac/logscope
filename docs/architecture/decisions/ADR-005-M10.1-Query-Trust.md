## Context

M11 introduced SQLite pushdown and FTS5 acceleration for M10 filter expressions. Wave 1 (`v2.13.0`) hardened **index integrity**. Wave 2 addresses **query answer integrity**: filters must not return different results depending on whether lines are evaluated in memory or via a persisted index.

Two defects violate this invariant:

1. **#198** — JSON field ordered comparisons always evaluate to false.
2. **#197** — `contains()` uses FTS5 pushdown that misses CJK substrings the in-memory evaluator finds.

Both produce plausible **zero-match** results.

---

## Decision

### 1. Semantic authority

`QueryEvaluator` is the **single semantic authority** for filter expressions. SQL and FTS pushdown are **optimizations** only.

### 2. Parity invariant

```text
memory path line numbers == persist-index path line numbers
```

for the same source, filter, and log format.

### 3. Capability detection

`QueryPlanner` may push `contains(message|content, term)` to FTS5 **only** when `ftsContainsIsFaithful(term)` is true. At minimum, terms containing non-ASCII bytes must not use FTS pushdown.

When pushdown is not faithful, fetch indexed lines and evaluate with `QueryEvaluator`.

### 4. JSON ordered comparisons (#198)

- Numeric literal + JSON field value that parses as a number → ordered comparison (`>`, `<`, `>=`, `<=`) uses numeric semantics.
- Numeric literal + non-numeric field value → line does not match.
- String literal + ordered operator → **reject filter** with explicit error (not silent zero matches).

Equality operators on JSON fields are unchanged.

### 5. Explicit failure over silent empty

Incorrect or unsupported semantics must **fail explicitly** or **fall back to the authority evaluator** — never return exit 0 with a false empty set when matches exist.

---

## Consequences

### Positive

- Investigators can trust query results across storage paths.
- Pushdown model stays additive; no second query language.
- Faithfulness gate pattern extends to future pushdown (e.g. ordered JSON SQL).

### Negative

- CJK `contains()` on large persisted indexes may scan more rows until a faithful FTS strategy exists.
- `service > "PCF"` changes from silent zero matches to explicit error.

### Out of scope

- Query cache algorithm (#196)
- New DSL features (P4)
