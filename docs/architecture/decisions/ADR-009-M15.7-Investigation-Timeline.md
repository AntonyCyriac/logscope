# ADR-009 Amendment: M15.7 Investigation Timeline (Story 3)

- **Status:** Accepted (amendment to ADR-009)
- **Date:** 06-08-2026
- **Parent ADR:** [ADR-009 Web Platform REST](ADR-009-Web-Platform-REST.md)
- **Release:** `v2.5.0` — Story 3: See What Happened
- **Prior amendment:** [ADR-009-M15.6 Multi-Source Investigation](ADR-009-M15.6-Multi-Source-Investigation.md) (`v2.4.0`)

---

## Context

Stories 1–2 (`v2.3.0`–`v2.4.1`) let users **collect** and **switch** investigation artifacts. Engineers still reconstruct incident order manually across files. Story 3 delivers a **chronological investigation narrative** by **merging** (not correlating) **timeline events** projected from artifacts.

**Mission:** Build a chronological narrative of an investigation.

Constraints unchanged: Investigation aggregate owns truth; C10 `ApplicationService` unchanged; manifest `schemaVersion: 1`; file-first persistence; no correlation engine, crash analysis, or ADR-010 events in this release.

M9 `TimelineAnalyzer` remains **session-scoped** histogram analysis on one analyzed log. Story 3 introduces a separate **investigation timeline** read model across artifacts.

---

## Decision

### 1. Timeline is a projection

Timeline is **always derived**. Never authoritative storage.

```text
Investigation (authoritative)
    └── Artifacts
            └── IArtifactProjector (per type)
                    └── TimelineEvent[]
                            └── TimelineProjector (merge + paginate)
```

| Layer | Persisted? |
|-------|------------|
| Investigation manifest + artifact files | **Yes** |
| `TimelineEvent` stream | **No** — computed on demand |
| Optional `.timeline-cache.json` | **Ephemeral** — invalidated when `manifest.updatedAt` changes |

Timeline code references **`TimelineEvent` only** — not `LogLine` or raw log files.

### 2. TimelineEvent

Core domain object for the narrative view:

```cpp
struct TimelineEvent {
    std::string id;           // stable — deep links, future annotations
    std::string timestamp;    // ISO-8601 UTC
    std::string artifactId;
    std::string eventType;    // log.line | note.created | artifact.attached | ...
    std::optional<std::string> severity;
    std::string message;
    EventSource source;
    std::map<std::string, std::string> metadata;
};
```

**Stable `id`:** deterministic from `(investigationId, artifactId, sequence, timestamp, eventType)`.

### 3. Artifact projectors (open/closed)

```cpp
class IArtifactProjector {
public:
    virtual std::string_view artifactType() const noexcept = 0;
    virtual void project(const ArtifactRecord& artifact,
                         const foundation::Path& dataPath,
                         const ProjectOptions& options,
                         TimelineEventSink& sink) const = 0;
};
```

| Projector | Artifact type | Events (v2.5.0) |
|-----------|---------------|-----------------|
| `LogArtifactProjector` | `log` | One event per parseable timestamped line (capped) |
| `NoteArtifactProjector` | `note` | One `note.created` at `importedAt` |
| `PStackArtifactProjector` | `pstack` | One `artifact.attached` marker |
| `CoreArtifactProjector` | `core` | One `artifact.attached` marker with `sizeBytes` |

New artifact types add a projector + handler without changing merge/sort/pagination logic.

### 4. Chronological merge (not correlation)

- Normalize all timestamps to **UTC** at projection time.
- **Sort key:** `(instantUtc, artifactId, sequenceWithinArtifact)`.
- **Default order:** `asc` (oldest first — narrative order).
- **No** transaction-ID joins, visual correlation lines, or causality labels in Story 3.
- Unparseable log lines: **omitted** (no synthetic timestamps).
- Clock skew: **not** corrected in Story 3.

### 5. Performance

- **Lazy, streaming** per-artifact scan — no eager merge of multi-GB logs.
- **Pagination required:** `limit`, `offset` (cursor later).
- Per-artifact and global event caps; `truncated: true` when capped.
- Reuse analysis timestamp parsing when index/snapshot sidecar exists.

### 6. Navigation (jump to source)

Each event carries `EventSource` (`artifactId`, `artifactType`, `artifactName`, optional `lineNumber`).

| Surface | Behavior |
|---------|----------|
| **Web** | Click event → open artifact; highlight line when `lineNumber` set |
| **CLI** | Print `artifactId` + line; `investigation open --artifact` |
| **REST** | Event JSON includes `source` object |

### 7. API

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/v1/investigations/{id}/timeline` | Returns **timeline events** (domain JSON), not rendered HTML |

Query: `limit`, `offset`, `order=asc|desc`.

Response includes `pagination.truncated` and optional `warnings[]` when a projector skips an artifact.

### 8. CLI parity

```text
investigation timeline <id> [--format json|table] [--limit N] [--order asc|desc] [--dir <root>]
```

### 9. Manifest

**No schema bump.** Timeline is not stored in `manifest.json`.

### 10. Out of scope (Story 3)

- Correlation engine (transaction/request ID joins)
- Visual correlation (lines, grouping)
- Crash analysis on `core` (Story 4)
- Causality / root-cause labels
- Real-time tailing timeline
- ADR-010 domain events
- Replacing M9 session timeline charts

---

## Consequences

- **Positive:** Chronological narrative across artifacts; extensible projector registry; jump-to-source closes evidence loop; API supports lazy/streaming evolution.
- **Negative:** Large investigations require pagination; undated log lines absent from timeline; cross-artifact order reflects file timestamps only.
- **Neutral:** Story 1–2 investigations unchanged; active log switch (M15.6) orthogonal to timeline projection.
